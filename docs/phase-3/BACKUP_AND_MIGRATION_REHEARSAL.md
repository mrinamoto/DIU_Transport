# Backup and Migration Rehearsal

Date: 2026-08-05

## Safe commands and observed result

```powershell
npm run db:backup
npm run db:backup:verify
npm run db:export
```

The rehearsal completed successfully against fictional development content. Backup created a new timestamped file under ignored `backend/backups/`, verified `integrity_check` on source and destination, and did not overwrite an existing file. Restore verification copied the backup to a unique temporary database, enabled foreign keys, verified integrity, schema version 2, required tables, and safe row counts, then removed only the temporary copy. The original source and backup remained present and unchanged.

Export created a timestamped ignored JSON bundle under `backend/exports/` with schema version, table list, row counts, keys, timestamps, and non-sensitive rows. User name/email/password hash and driver name/phone values are excluded. No row credential or contact value is printed by the scripts.

The tracked development database was restored byte-for-byte to its initial Git version after rehearsal; final isolated tests use temporary databases. No unknown database was modified or deleted.

## Operations behavior

- `better-sqlite3.backup()` supplies SQLite-aware online backup behavior.
- Missing source files and pre-existing output paths fail clearly.
- Output names use UTC timestamps and never overwrite.
- Verification is non-destructive and never restores over the active path.
- Export is a rehearsal artifact, not an import script or compatibility claim.

## PostgreSQL mapping notes for a future approved phase

| SQLite concept | Candidate PostgreSQL treatment | Required review |
|---|---|---|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` / bigint identity | Preserve imported IDs and reset sequences safely. |
| `TEXT` timestamps | `date`, `time`, or `timestamptz` by semantic field | Define Dhaka/UTC policy; reject malformed historic values. |
| text status/role checks | PostgreSQL check constraints or managed enums | Inventory values before enum creation; plan enum changes. |
| SQLite booleans/0/1 | native `boolean` | Validate every source value. |
| foreign keys | PostgreSQL foreign keys | Load parent rows first or defer constraints in a controlled transaction. |
| `COLLATE NOCASE` unique index | normalized generated column, `citext`, or functional `lower()` index | Decide locale/case rules and detect duplicates first. |
| JSON text metadata | `jsonb` | Parse/validate every row and preserve the metadata allowlist. |
| SQLite `strftime` defaults | PostgreSQL time defaults | Standardize precision and timezone. |

Checks, composite uniqueness, route-stop ordering, schedule overlap behavior, foreign-key actions, audit indexes, and active-status indexes must be recreated and tested. SQLite SQL functions, affinity/coercion, case collation, autoincrement semantics, transaction locking, and date comparisons differ from PostgreSQL. Cleanup must identify duplicate normalized names, invalid dates/times, orphan keys, unexpected enum/status values, malformed JSON, and 0/1 values outside the intended boolean domain.

## Limitations and rollback

Phase 3 does not provide an active-database restore command because replacement requires an explicit operator-selected target, outage/locking plan, independent backup, and approval. Rollback for migration 002 is restore into a separate target from a verified backup; no destructive down migration was introduced. No PostgreSQL server, schema, import, or compatibility test was executed.
